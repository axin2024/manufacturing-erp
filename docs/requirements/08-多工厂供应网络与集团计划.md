# 制造与贸易集团 ERP 2.0 产品需求文档

**多工厂供应网络与集团计划**

需求评审版 · 2026-11-26 · 计划基线 v1.1.0（92ffe2f）

## 产品目标与交付边界

当前发行覆盖物料计划、车间工单与业财关期。本版支持以下业务流程。集团计划员比较两个工厂的供需缺口，批准跨厂调拨，双法人收发结算并在合并视图抵销。 [现有项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

首期采用单币种同集团交易，不足产能的建议保留待接单状态。计划供给按已释放工单和在途调拨净额计算。

## 使用者与工作台

集团计划员建情景，工厂计划员认领，仓管按本厂过账，集团财务看抵销。

集团供需板按厂、周和物料展开缺口。拖动计划交期前预览承诺变化，分厂只能确认本厂产能。集团财务从抵销差异钻取收货批和两边凭证。

| 需求 | 模块 | 产品行为与约束 | 验收 |
| --- | --- | --- | --- |

| R2 | 滚动预测 | 按周导入需求，销售订单消耗同周期预测，保留预测偏差与来源。 | A3、A4 |
| R3 | 情景模拟 | 复制冻结供需，比较自产、委外和调拨路径，解释缺料与交付差异。 | A5、A6 |
| R4 | 集团审批 | 计划员提交分厂建议，各厂确认产能，主管按版本发布选定行。 | A7、A8 |
| R5 | 跨厂物流 | 按批次拣货、登记在途、目的厂分批验收，短溢收转差异单。 | A9、A10 |

## 页面操作与回执

| 关联需求 | 角色与入口 | 操作细节 | 需要读回的字段 |
| --- | --- | --- | --- |
| R1 · 网络建模 | 主数据员/网络维护 | 选定源厂、目的厂、物料和起运日预览预计到货 | lane_id、arrival_date |
| R2 · 滚动预测 | 计划员/需求消耗 | 展开预测行查看抵扣它的客户订单与未消耗量 | forecast_line、consumed_qty |
| R3 · 情景模拟 | 计划员/情景对比 | 锁定同一需求集逐厂比较三方案的交期与成本 | scenario_rev、shortage_qty |
| R4 · 集团审批 | 厂长/发布确认 | 只签认本厂建议行，写入承诺日期和责任中心 | approval_id、selected_line_ids |
| R5 · 跨厂物流 | 仓管/在途台账 | 按调拨号配对出库批次与目标库位，短收创建差异 | shipment_lot、variance_id |
| R6 · 内部结算 | 合并会计/抵销底稿 | 按内部交易号配对应收应付，定位单边差额 | pair_id、remaining_minor |

批次和单位换算由原物料主数据提供。试算报告分别列需求量、可用量、已承诺量、在途量，分配后各厂可用数量均须大于等于零。

## 状态、权限与数据

调拨建议→双厂确认→已发运→部分到货→收齐→已对清。差异保留责任工厂和待处理数量。

数量按物料基础单位，运输提前期用目的厂日历。抵销分币种和期间，差额须能回到具体收发两端。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `site_calendar(site,shift)`
- `network_lane(source,dest,lead_days)`
- `plan_scenario(base_rev,horizon)`
- `transfer_line(from_site,to_site,qty)`
- `elimination_pair(ship_entry,receive_entry)`

发布按情景版本和建议行编号唯一，调拨收发分别保留两厂本地单号。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /network-plans/{id}/publish`。请求必填字段为 `revision, selected_line_ids, horizon_end`。成功回执提供 transfer_ids, production_ids, blocked_lines。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "revision": 3,
  "selected_line_ids": [
    "L8",
    "L9"
  ],
  "horizon_end": "2027-03-31"
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "transfer_ids": [
    "T8"
  ],
  "production_ids": [
    "P9"
  ],
  "blocked_lines": []
}
```

冻结后物料版本变化返回 409 并列出 L8，操作员需重新试算后再发布。

## 升级、部署与恢复

为存量工单绑定原工厂，未确认归属的库存列入迁移差异表，原账套总额必须配平。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对两边库存批号、在途数量及对账凭证。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

负载报告须记录机器及依赖版本、预热和采样时长、成功数、拒绝数和超时数。验收人从工作台与业务记录两侧核对 A13，并附上原始输入、回执和最终状态。

### A13 计量口径

以件为基础单位。发出、已收和在途三列须满足发出等于已收加在途。独立盘亏处置后应追加差异单，不能覆写收货历史。

## 分期交付

1. **供需网络及冻结。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **多厂计划与执行。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **抵销与集团报表。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
