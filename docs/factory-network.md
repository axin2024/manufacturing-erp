# 多工厂计划操作说明

## 建立工厂归属

管理员在「工厂运输网络」登记工厂。计划员在各自法人账套启用工厂物料，再维护起运厂、目的厂和运输工作日。线路的两个法人都要授予维护人计划权限。预计到货按目的厂工作日计算，周末默认休息，可以登记调休或停产日。

升级旧账套时，先在隔离副本打开「库位与工单归属核对」，按物料、基础单位和质量状态核对账面数量。页面显示库位和工单的总数及未归属数。单厂账套可分批扫描，工单还需要对应的物料资格。多厂账套将待处理编号列入差异清单，由管理员指定所属工厂。一次处理会同时提交归属、差异和游标。关闭页面后再次打开可从游标继续。原工单号、库存批号和库存流水继续沿用。

旧版升级操作顺序如下。

1. 用原库备份建立隔离副本。让 2.0 CLI 的 `ERP_DSN` 指向副本，先运行 `php bin/erp.php network-preflight 1 > before.json`。将示例中的 1 换成实际集团编号。命令可在 1.1 数据结构上运行，列出各法人的待归属编号、逐物料数量、库存账面金额和逐表摘要。
2. 运行 `php bin/erp.php migrate`。登录工作台，进入「工厂运输网络 → 库位与工单归属核对」，分批处理或指定工厂。多厂共用的旧法人需要按原始单据确认实际工厂。再次运行预检，比较两份文件各法人下的 `ledger`，核实 `ownership` 里的待处理清单已清空。
3. 集团各法人的管理员在归属核对页选择「启用集团计划」。未启用的集团只开放基础设置。退出试点时选择「停止受理新计划」，已提交的建议仍可签认和发布，已发出的批次可继续收货、处理差异和财务对清。切换法人并导出未决单据 CSV，可以分别跟踪待签建议、未发货、实际在途、差异单、在制工单和待确认对清的单据。[旧账套迁移前后数据](validation/network-upgrade.json)

跨厂采用不同料号时，由拥有双方计划权限的负责人在目的法人维护线路上的一对一等效资格。选择起运料号、目的厂料号和工程批准号。两料号基础单位须一致。源批按起运料号出库，目的子批按获准的当地料号入库，调拨详情保留两个编码和原批号。撤销或更改资格会使尚未发布的旧情景需要重新试算。

## 导入周预测

在「周预测与订单消耗」上传 UTF-8 CSV，使用当前法人账套中已启用的工厂和物料编码。数量采用基础单位，支持三位小数，周起始取周一。每个批次内同一工厂、物料、周只能出现一次。表格中任何一行不合格，整批回滚。仓库提供两周的输入样例。[示例文件](../examples/network-weekly-forecast.csv)

销售或计划人员将销售交付行分配到实际供应工厂。冻结销售单后，展开预测行可以看到订单号、交期及该笔抵扣量。预测 100 件、当周有效接单 40 件时，剩余独立需求为 60 件。跨周拆分的交付各自消耗对应周的预测。取消交付时，已发货数量仍计入实际订单量。

相同批次、相同文件可以重传。修订数据使用新批次，仅替换文件中列出的工厂、物料和周；旧预测行保留来源批次及最新有效行号。周预测未被订单消耗的部分按周日到期，订单本身按具体交货日排入试算。

## 比较与执行集团计划

1. 集团计划员在「集团供需情景」选择工厂和日期范围。各厂先覆盖自身需求，再按照运输线路使用可调库存。明细区列出各厂净需求、已分配库存、已释放工单、已发运在途、已签执行单以及剩余缺口。
2. 展开情景可以比较调拨、自产和委外的交期、参考单价及资格限制。派生版本可以沿用冻结输入，也可以读取新库存和订单重新计算。物料清单、工艺和供需变化后，已有情景继续展示原建议。
3. 计划员选定建议行并提交。每个法人的管理员在「分厂产能签认」给实际签认人授权。签认人只能处理授权工厂的建议，填写责任中心、承诺日期及依据。调拨由起讫两厂分别签认，未接单或否决的工厂会出现在发布回执中。
4. 主管在情景内发布选中的建议。物料或供需信息变化会要求重新试算。成功的自产建议创建实际工单，调拨建议创建调拨单。再次提交相同请求可以取回原执行单号。

接口调用沿用登录会话和 CSRF 保护。向 `POST /network-plans/{id}/publish` 发送 JSON，请求使用 `X-CSRF-Token` 和 `Idempotency-Key`。请求体填写 `revision`、`selected_line_ids` 和 `horizon_end`。返回的 `transfer_ids`、`production_ids` 和 `blocked_lines` 分别给出调拨单号、工单号和仍需处理的行。会话须切换到创建该情景的法人。发布主管还须持有所选各法人的计划权限。

在情景详情选择一条建议，将「相对需求日调整天数」向前或向后拖动，点击「查询」。预览按冻结路径最早可用日和两厂最近有效的签认日期推算可交日，显示提前要求交货时涉及的缺量。预览可反复比较，同一条建议仍保留原需求日。实际承诺变更由工厂在签认入口登记。

## 从仓库批次查到法人账

发货前，管理员在「跨厂在途台账」将仓管授权给实际经办工厂。起运厂选择调拨单、已有批号及库位，填写本厂发运单号与实发量。目的厂按到货批次填写本厂收货单号、库位、预计量和实点量。一张发运单可以关联多张收货单，各张收货单都能查回起运批号。

发出 80 件、实点 78 件时，目的库增加 78 件，2 件继续列在在途台账。后续补到货时选择原短收差异单。如果实点数量超过预计量，超出部分登记溢收。实际退回后填写承运人交接凭据，可以回查经办人、数量和登记时间。网络中断后使用相同单号和原始数据重试。

从「集团往来抵销」选择起止月份内的具体日期。报表逐笔比较发运应收及已验收应付，按币种汇总。点击内部交易编号可回到收货子批和双方法人凭证。转移单价每件 10 元时，发 80 件形成 800 元应收，收 78 件形成 780 元应付，差额 20 元继续列示。跨月补收后仍可用一月末日期查回原来的单边金额。

短收经双方确认由目的厂承担时，目的法人财务可凭责任协议登记独立盘亏单。在同一法人内借记物料损耗、贷记在途存货，跨法人时目的账套借记物料损耗、贷记内部应付。原收货量保留。调拨详情单列累计未签收数量中的已认定盘亏与可继续验收数量。盘亏凭证按其实际记账期进入集团底稿。所有数量均有去向且凭证配平后，财务填写对清日期和核对依据。

本版在同一集团、同一本位币内配对。跨厂等效资格支持相同基础单位的一对一替代。工作日例外由工厂维护。恢复后的外部承运人交接单、盘亏责任协议由经办人按系统保留的证据编号对照原件。

## 重现恢复演练和容量验收

Windows 上准备 PHP CLI、PDO MySQL 和 MySQL 8.4 服务端及客户端工具。以下命令从仓库根目录运行。演练会创建两套独立的临时数据库，写入合成业务，导出并还原备份，终止恢复实例，再重启并按原请求号重发收货。数据库、备份、运行日志和结果 JSON 都保留在命令输出的临时目录。

```powershell
.\tests\network-recovery.ps1 -MysqlBin 'C:\mysql\bin'
```

在已迁移的隔离库中设置 `ERP_DSN`、`ERP_DB_USER`、`ERP_DB_PASSWORD` 和 `ERP_TEST_DATABASE=1`，运行 `php tests/network-capacity.php`。脚本生成 10 厂、100 种物料、10,000 条周预测、9,999 个库存批次和 1 张已释放工单。一次预热后连续试算三次，每次都冻结并保存一份独立的 90 天情景。计时从请求冻结到数据库事务完成，造数和发布后的核对独立进行。这组数据为单法人、单计划员顺序提交，跨法人收发使用独立的恢复用例验证。[容量样本](validation/network-capacity.json) · [恢复输入、回执与库存及财务读数](validation/network-recovery.json)
